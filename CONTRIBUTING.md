# Contributing

1. Create a focused branch: `feature/<issue>-<slug>` or `fix/<issue>-<slug>`.
2. Add or update tests with every behavior change.
3. Run `./scripts/verify.sh` before opening a pull request.
4. Use Conventional Commits.
5. Update ADRs when changing architecture or dependency direction.
6. Never commit secrets, personal data, generated binaries, or local `.env` files.

Pull requests require successful build, tests, formatting, architecture rules, dependency review, and security checks.
