# ADR-0056: Publisher dashboard in the portal

## Status

Accepted

## Context

Phone sign-in, listing creation, photos, contact options and publication all existed only as
API routes. Publishers need a simple Arabic interface that works on phones. That interface must
not expose access tokens to browser JavaScript.

## Decision

The portal acts as a backend-for-frontend for authenticated work:

- `/login`: the publisher enters a phone number in any common local format (`09…`, `9…`,
  `+963`/`00963`, Arabic-Indic digits, spaces or dashes), which is normalised to E.164. They
  then enter the 6-digit code. Verification calls the API from a server action and stores the
  access token in an `httpOnly`, `SameSite=Lax` cookie (`Secure` in production) that expires
  with the token. The token never reaches client JavaScript.
- All authenticated API calls run on the portal server (server actions, server components and
  route handlers), which add `Authorization: Bearer`. Next.js server actions provide built-in
  origin checks against cross-site form posts. A `401`/`403` from the API sends the user back to
  sign-in.
- Middleware redirects `/my/*` to `/login?next=…` when no session cookie is present. `next` must
  be a same-site relative path, which prevents open redirects.
- `/my`: the publisher's listings with status (Draft/Published) and sign-out.
- `/my/new`: one form for property, location, Syrian details, features, offer, price (amount and
  currency, or on request) and contact options. It is validated on the server with Arabic field
  messages and entered values kept. It creates the Property and the Listing, then applies the
  publication data in one `PATCH`. If contact cannot be enabled because the account has no
  verified phone, the Draft is still saved and the publisher is told why.
- `/my/listings/{id}`: upload photos (multiple files, sent one per server action and capped at
  11 MB by `serverActions.bodySizeLimit`), delete photos, see the cover, and publish. Draft photos
  are streamed through `/my/photo/{listingId}/{photoId}`, which adds the session token, with
  `private, no-store`.
- The header shows "أضف إعلانك" (Add your listing) or "إعلاناتي" (My listings) depending on the
  session.
- `PORTAL_PUBLIC_URL` sets `metadataBase` for absolute Open Graph URLs.

## Consequences

Publishers can sign up, create a listing with photos and publish it from a phone, without
handling tokens. Sessions last as long as the access token (60 minutes by default) and are not
refreshed. Refresh tokens or sliding sessions are open work, as are editing published listings
(ADR-0029) and deleting Draft listings.
