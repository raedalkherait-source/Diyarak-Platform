# ADR-0065: Maps with approximate public locations

## Status

Accepted.

## Context

Location is the first question buyers and tenants ask, and the platform already stores optional
coordinates on a property (`address.location`). Publishing exact coordinates, however, reveals
where a private owner lives, and listing photos already have GPS data stripped for the same
reason (ADR-0055). There was also no way to set the coordinates from the portal.

## Decision

- **Coordinates never leave the API exactly.**
  - The public listing representation gains `property.location.approximate =
    { latitude, longitude, radiusMeters }`.
  - The point is snapped to a 0.004° grid: roughly 450 m north–south and 370 m east–west in
    Syria. `radiusMeters` is 500.
  - The exact value stays in the database. Only the owner sees it, through the management API.
  - The ETag representation revisions are bumped to `v4`.
- **Portal, create and edit:** an optional map pin.
  - The form sends `latitude`/`longitude` together.
  - The pin must be inside a bounding box around Syria and is rounded to 6 decimals.
  - Clearing the pin removes the stored location.
  - The edit merge treats `address.location` as portal-managed (ADR-0063 merge rules otherwise
    unchanged).
- **Portal, display:**
  - The listing page shows a 500 m circle, never a marker, labelled as approximate.
  - The search page offers a collapsible map of the current results. The map loads only when it
    is opened.
- **Map library:** Leaflet 1.9, loaded on the client only.
  - Markers are vector circles, so no image assets are needed.
- **Tiles** are configured at runtime through `MAP_TILE_URL` and `MAP_ATTRIBUTION`.
  - The default is OpenStreetMap's public tiles, acceptable for launch traffic.
  - The runbook explains switching to a provider account when traffic grows, in line with the
    OSM tile usage policy.

## Consequences

- Listings in the same grid cell share a map position. The search map shows overlapping markers
  rather than clustering them; clustering can be added when density requires it.
- The map tiles come from a third-party host, so visitors' browsers contact that host. No
  personal data is sent beyond what any web request carries.
