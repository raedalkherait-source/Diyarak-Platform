# ADR-0039: Anonymous paginated Published Listing collection

## Status

Accepted and implemented.

## Context

ADR-0038 introduced anonymous direct loading of a known `Published` Market Listing through `GET /api/market/public/listings/{listingId}` with a deliberately reduced publication-facing projection.

A public collection is the next required transport capability, but search ranking, filtering, recommendation, public Property projection, and business ordering semantics remain undefined. An unbounded collection would also create an avoidable scalability problem.

## Decision

`Diyarak.Api` exposes:

`GET /api/market/public/listings?page={page}&pageSize={pageSize}`

The route is anonymous and remains mapped independently of ADR-0025 OIDC management authentication.

Pagination is transport-oriented only:

- `page` defaults to `1` and must be positive;
- `pageSize` defaults to `20`, must be positive, and may not exceed `100`;
- invalid or duplicate pagination values return `400 Bad Request` with `market.listing.invalid_public_pagination`;
- results are ordered deterministically by `ListingId` ascending before paging;
- this ordering is not a search or ranking contract;
- the response returns `items`, `page`, `pageSize`, and `hasMore` and intentionally omits `totalCount`.

Only `Published` Listings are eligible. Draft Listings are excluded in the PostgreSQL query. Application orchestration fails closed if the published-query port ever returns a non-published Listing.

Each item uses the same reduced public projection as ADR-0038:

- `listingId`;
- `context`;
- `headline`;
- `price`;
- optional `availableFromDate`.

The collection does not expose management version/status, `PublisherUserId`, or subject identifiers. Public Property/subject representation remains a separate requirement.

`Diyarak.Market.Application` owns the read port `IPublishedListingQuery`. The PostgreSQL adapter implements it as a no-tracking filtered query over `market.listings`, ordered by identifier and using `Skip`/`Take`. The use case requests one extra row to determine `hasMore` without issuing a total-count query.

## Consequences

Public clients can enumerate published Listings safely in bounded pages without authentication.

The initial pagination contract is deterministic but deliberately not relevance-ranked. Search filters, sorting choices, recommendation logic, total counts, and cursor pagination may be defined separately when concrete product requirements exist.

No database migration is required.
