# ADR-0068: Real-estate agency pages and verification

## Status

Accepted.

## Context

Much of the Syrian market goes through real-estate offices (مكاتب عقارية). Visitors want to know
whether a publisher is a known, licensed office. Offices want a page that gathers their listings,
and agency packages (phase 3) need an agency to attach to.

## Decision

- **Domain:** the `Agency` aggregate lives in the `Diyarak.Market.Company` module, which depends
  only on the shared kernel.
  - One agency per user, enforced by the unique index `ux_market_agencies_owner_user_id`.
  - Profile fields: name (2–80 characters), description, governorate and city.
  - Verification states are None, Pending, Verified and Rejected. Requesting verification needs a
    commercial registration or licence number. A rejection needs a note.
  - **Renaming a verified or pending agency resets it to None**, so a verified name cannot be
    turned into a different identity.
- **Storage:** `market.agencies` (migration `MarketAgencies`), with optimistic concurrency on
  `version` and check constraints that tie `verified_at` and `registration_number` to the
  verification status.
- **API:**
  - Owner: `GET` and `PUT /api/market/agency`, and `POST /api/market/agency/verification`. The
    owner's view includes the registration number.
  - Public: `GET /api/market/public/agencies/{id}?page=` returns the profile and the agency's
    published listings, newest first, through the new `PublisherUserId` search criterion. It
    never includes the owner or the registration number.
  - Moderators: `GET /api/moderation/agencies` (pending), and
    `POST /api/moderation/agencies/{id}/verify|reject`.
  - Public listings carry `agency: { agencyId, name, verified }`. The agency's id and version are
    part of the listing ETag, so a rename or a new badge invalidates cached responses. The ETag
    revisions are bumped to v5.
- **Portal:**
  - `/my/agency` to create and edit the profile and to request verification.
  - The public page `/agencies/{id}`, with RealEstateAgent structured data. It stays `noindex`
    until the agency is verified.
  - On a listing page, the publisher line links to the agency page and shows "✓ موثّق" when the
    agency is verified.
  - `/admin` gains a queue of verification requests.
  - Saving an agency profile and a moderator's decision both invalidate the portal's listing
    cache.

## Consequences

- Verification is a manual review. The number is stored so moderators can check it against the
  licensing authority; documents are exchanged outside the platform for now.
- An agency is a single account. Staff accounts under one agency come with agency packages.
