# ADR-0067: Publisher statistics

## Status

Accepted.

## Context

Publishers cannot tell whether a listing works: how many people saw it, asked for the number or
saved it. Without that, they have no reason to improve a listing, and later no reason to pay for
featured placement (phase 3).

## Decision

- **Storage:** `market.listing_daily_statistics (listing_id, day, views, contact_reveals)`.
  - Days follow the Damascus calendar (UTC+3).
  - Each event is a single `INSERT … ON CONFLICT DO UPDATE` increment, so concurrent events never
    lose a count.
  - Only daily aggregates are kept: no visitor identifiers or IP addresses.
- **Views:**
  - The listing page sends a beacon to the portal route `/api/view/{id}`, once per listing per
    browser session (`sessionStorage`).
  - The portal drops crawlers, link-preview fetchers and headless tools by user agent.
  - It forwards signed-in viewers to `POST /api/market/listings/{id}/views`, so a publisher's
    views of their own listing are not counted. Others go to the anonymous
    `POST /api/market/public/listings/{id}/views`.
  - Both endpoints use the per-IP `view` rate-limit policy (120 per hour by default), always
    return `204`, and count only published listings.
- **Contact reveals:** counted in `GetListingContactUseCase` when the number is actually returned.
- **Favorites:** the current number of users who saved the listing, from `listing_favorites`.
- **API (owner only):**
  - `GET /api/market/listings/{id}/statistics?days=7..90` returns totals and every day of the
    period, including days with zero activity.
  - `GET /api/market/listings/statistics?days=` returns totals per listing for the dashboard.
- **Portal:**
  - **Listing editor:** three stat tiles and a single-series bar chart of daily views. The chart
    reads right to left (oldest on the right), uses the brand colour token in light and dark
    modes, gives each bar a hover title, and offers a table view.
  - **`/my`:** shows the 30-day totals for each listing.

## Consequences

- The counts are approximate. One person on two devices counts twice, and a determined client can
  inflate a count only within the rate limit. That is acceptable for guidance, but these counts
  must not be used for billing.
- The table grows by at most one row per listing per active day.
