# ADR-0070: SMS alerts for saved searches

## Status

Accepted. Extends ADR-0066.

## Context

Saved searches showed new-listing counts only inside the site, so visitors had to come back to
notice them. Every SMS costs money, and users dislike frequent or night-time messages.

## Decision

- **Opt-in per saved search** (`alerts_enabled`), toggled with
  `PUT /api/market/saved-searches/{id}/alerts { enabled }` and from `/my/searches`.
- **One summary SMS per user per day at most:**
  - A run counts listings published since each alerting search was last opened or last alerted,
    whichever is later.
  - It sends a single message with the total (capped at "+99") and a link to `/my/searches`.
  - The search is stamped **before** sending, so a crash can never lead to a second message.
  - A user is skipped if they were alerted in the last 20 hours.
- **Scheduling:**
  - A hosted worker runs every `IntervalMinutes` (default 60).
  - It sends only inside `WindowStartHour`–`WindowEndHour`, Damascus time (default 10–20).
  - Each run is capped at `MaximumUsersPerRun` messages (default 200).
  - A failed run is logged and retried on the next tick.
- **Delivery:** the configured HTTP SMS gateway (ADR-0059) gains `SendTextAsync`. Alerts need a
  gateway whose parameters use `{message}`; Twilio does. Development without a gateway logs the
  message instead.
- **Off by default:** `SavedSearchAlerts:Enabled=false`. Enabling it in production without the
  SMS gateway fails at startup. Enable it on one API instance only.

## Consequences

- At most one SMS per opted-in user per day, which bounds the cost.
- Email or push alerts can reuse the same use case through another `ISavedSearchAlertNotifier`.
