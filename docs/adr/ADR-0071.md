# ADR-0071: Featured Listings and Payment Orders

## Status
Accepted — 2026-11-21

## Context
Diyarak needs a monetisation path so property owners can pay to have their
listings shown first in search results. Syria's payment landscape requires
manual verification: bank transfer receipts and mobile-money (Syriatel Cash,
MTN Cash) references are confirmed by a moderator, not an automated gateway.

## Decision

### Payment catalog
Products and methods are configured via `Payments:Products:{product}:Amount`,
`Currency` and `Payments:Methods:{method}` (instruction text). Two initial
products: **FeaturedListing7Days** and **FeaturedListing30Days**.

### Payment orders
A `PaymentOrder` tracks the lifecycle: **Pending → Confirmed | Rejected**.

- Only one pending order per listing (enforced by a partial unique index on
  `listing_id WHERE status = 'Pending'`).
- On confirmation the listing gains a `listing_promotions` row; if the listing
  is already featured the new period extends from the existing end date.

### Public projection
`PublishedListingProjection` gains `IsFeatured` (computed from
`listing_promotions`). The public query sorts featured listings first, then by
`FirstPublishedAt DESC`. The public response includes `featured: bool`; the
ETag revision is bumped to **v6**.

### Portal
- `ListingCard` shows a "★ مميز" badge for featured listings.
- The listing editor shows a "ميّز إعلانك" panel with the catalog, method
  instructions, a reference field and a submit button.
- The admin queue shows pending payment orders with confirm/reject actions.

### Endpoints
| Method | Path | Auth |
|--------|------|------|
| GET | `/api/market/payments/catalog` | user |
| GET | `/api/market/payments/orders` | user |
| POST | `/api/market/payments/orders` | user |
| GET | `/api/market/listings/{id}/promotion` | user |
| GET | `/api/moderation/payments` | moderator |
| POST | `/api/moderation/payments/{id}/confirm` | moderator |
| POST | `/api/moderation/payments/{id}/reject` | moderator |

## Consequences
- Moderators must check payment references manually; a future gateway
  integration can automate confirmation without changing the domain model.
- The catalog is configuration-driven; adding products or methods requires
  only an environment-variable change and a restart.
