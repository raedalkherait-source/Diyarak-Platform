# ADR-0054: Arabic public portal with Next.js

## Status

Accepted

## Context

The existing `Diyarak.Web` frontend is a single 1,300-line static JavaScript file in English. It
is rendered in the browser and served only in Development. A public marketplace needs
an Arabic right-to-left interface, mobile-first layouts for slow connections, and
server-rendered pages that search engines can index. Most marketplace traffic comes from search
engines.

## Decision

- Add `src/Frontend/Diyarak.Portal`, a Next.js App Router application in TypeScript, with exact
  dependency versions and a committed `package-lock.json`.
- Pages are rendered on the server from the anonymous public API: `/`, `/search` and
  `/listings/{id}`. Pages set Arabic titles and descriptions, and listing pages set Open Graph
  images from the cover photo.
- `lang="ar" dir="rtl"`, CSS logical properties, a system Arabic font stack (no web-font
  download), and light and dark colour schemes. On narrow screens the filters collapse behind
  a button so results appear first.
- The portal forwards only an allow-list of search parameters to the API. Prices use Western
  digits with `$` or `ل.س`.
- Listing photos are proxied through the portal origin (`/media/listings/...`), so pages need no
  cross-origin image configuration and CDNs can cache them under one host.
- Arabic labels for every API enum live in `lib/labels.ts`. A unit test parses the C# enum
  sources so labels cannot drift from the backend.
- CI gains a `portal` job: `npm ci`, tests, type check, production build.

`Diyarak.Web` remains in place for now. It should be retired once the portal covers its features.

## Consequences

The public site is indexable, Arabic-first and usable on phones. The portal has no
authentication yet. Phone sign-in, listing management, photo upload, and contacting the
publisher are follow-up work. The portal adds a Node.js runtime to production deployments
(`next start`).
