# ADR-0037: Owner-authorized Listing creation for Property subjects

## Status

Accepted and implemented.

## Context

ADR-0026 introduced authenticated Listing creation for an existing Property, but the initial workflow checked only Property existence. ADR-0034 later established immutable internal management ownership for new Properties, while intentionally leaving Listing subject authorization unchanged until a separate requirement was defined.

With persisted Property ownership now available, existence-only Listing creation would allow any mapped user who knows a Property identifier to create a Listing that references another user's Property. Delegated publication authority, agency relationships, company authority, and ownership transfer are still undefined.

## Decision

For the current Property subject type, Diyarak authorizes Listing creation only when the mapped internal actor is also the persisted Property management owner.

`CreateListingUseCase` depends on the Application-owned `IPropertyListingAuthorizationChecker`. The PostgreSQL implementation performs a no-tracking query that succeeds only when both the Property identifier and `OwnerUserId` match the supplied actor.

The authorization check executes inside the existing ADR-0027 `ReadCommitted` Listing-creation transaction. No Property row lock or stronger isolation level is introduced. Property ownership is immutable in the current model, and Property removal is not defined.

Missing Properties, Properties owned by another user, and legacy Properties whose `owner_user_id` is `NULL` are deliberately concealed behind the existing creation conflict `market.listing.property_not_found`. The response does not reveal whether a non-authorized Property exists.

The request still accepts only the Property identifier. `PublisherUserId` continues to come exclusively from the mapped internal actor.

No delegated publication authority, agency grant, company role, administrator override, Property ownership transfer, or legacy ownership assignment is introduced by this decision.

## Consequences

A mapped user can no longer create a Listing for another user's Property merely by knowing its identifier. New actor-owned Properties created under ADR-0034 can be listed by their owner. Legacy-unowned Property rows cannot be used for new Listing creation until an authoritative ownership assignment or a future delegation model explicitly permits it.

`IPropertyExistenceChecker` remains in use for publication-time subject availability. Listing creation uses the narrower owner-aware authorization port instead of existence-only validation.

Future delegated publication, agency/company authority, administrative overrides, and any stronger transaction isolation remain separate requirements.
