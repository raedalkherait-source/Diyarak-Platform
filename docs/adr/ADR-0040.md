# ADR-0040: Published Listing collection persistence index

## Status

Accepted and implemented.

## Context

ADR-0039 introduced anonymous bounded enumeration of `Published` Market Listings through `GET /api/market/public/listings`. The PostgreSQL adapter filters `market.listings` by persisted `status`, orders by `id`, and then applies bounded pagination.

The existing table has a primary-key index on `id`, but no index beginning with `status`. As the Listing table grows, the public collection should have a persistence index aligned with its confirmed filter and deterministic technical ordering without changing the public API or inventing search semantics.

## Decision

`MarketListingRecord` defines a non-unique composite index over:

1. `Status`;
2. `Id`.

The PostgreSQL database index is named:

`ix_market_listings_status_id`

The `MarketPublishedListingQueryIndex` migration creates the B-tree index on `market.listings(status, id)` and removes it on rollback.

The index exists to support the confirmed ADR-0039 access pattern: equality filtering by publication status followed by deterministic identifier ordering. PostgreSQL remains free to choose the execution plan for a particular query and data distribution.

No Application, Domain, Host, pagination, ordering, ranking, filtering, or response contract changes are introduced.

## Consequences

The persistence model now exposes an index that matches the public collection's confirmed predicate and ordering.

Future search, ranking, semantic sorting, geographic filtering, price filtering, or other discovery requirements may require separate indexes or a dedicated search/read model and must not be inferred from this index.

A database migration is required.
