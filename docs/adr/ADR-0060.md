# ADR-0060: Single-server container deployment

## Status

Accepted

## Context

The repository had only a local development `compose.yaml` and no production packaging. The
platform needs a launch setup that one operator can run on a single rented server: HTTPS,
automatic migrations, backups and secrets kept out of source control.

## Decision

- `deploy/Dockerfile.api` (context: repository root) uses multi-stage builds:
  - The `build` stage is pinned to `mcr.microsoft.com/dotnet/sdk:10.0.201`, matching
    `global.json`, and copies `.editorconfig`, because analyzer severities live there and warnings
    are errors.
  - The `migrations` target is a self-contained EF Core bundle on `runtime-deps`.
  - The `api` target runs on `aspnet:10.0` as the non-root `app` user, on port 8080, with
    `/var/lib/diyarak/media` for photos and a readiness health check.
- `deploy/Dockerfile.portal` (context: the portal) builds Next.js with `NEXT_OUTPUT=standalone`
  and runs `node server.js` as the non-root `node` user, with a health check on `/api/health`.
  Standalone output is enabled only through that variable, so local `next start` keeps working.
  The image went from about 1.1 GB to 352 MB.
- `deploy/compose.production.yaml`:
  - `postgres:17-alpine` on a private network with no published ports.
  - `migrations`, which must complete successfully before the API starts.
  - `api`, configured from `deploy/api.env` and given the connection string.
  - `portal`, which calls the API over the internal network.
  - `caddy:2-alpine`, which handles automatic HTTPS for the portal and API domains, adds HSTS,
    removes the `Server` header and limits request bodies to 12 MB.
  - `backup`: a periodic `pg_dump` (custom format) plus a media tarball, with retention.
  - Named volumes for data, media, backups and Caddy state.
- The internal network has the fixed subnet `172.28.0.0/24`. The API trusts `X-Forwarded-For`
  only from that network, through the new `ReverseProxy:KnownNetworks` setting (CIDR, validated,
  and never `/0`). Caddy sets the client address itself.
- Secrets live only in the untracked `deploy/.env` and `deploy/api.env`. `*.example` templates are
  committed.
- CI builds all three images and validates the compose file.
- `docs/runbooks/production-deployment.md` covers installation, updates, rollback, backup and
  restore, monitoring and security.

## Consequences

The full stack was built and run locally. The checks covered:

- the migrations applied;
- HTTPS through Caddy with HSTS, and an HTTP to HTTPS redirect;
- the portal and API health checks;
- the guarded dashboard routes;
- the SMS failure path (`503`);
- a scheduled backup;
- a successful `pg_restore` drill into a scratch database.

A single server is a single point of failure. Backups must also be copied off the server, and
the operator must run restore drills. Object storage for photos, a managed database and
monitoring are the next steps as traffic grows.
