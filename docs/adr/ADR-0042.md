# ADR-0042: Bounded authenticated Market management collections

## Status

Accepted and implemented.

## Context

ADR-0033 and ADR-0035 introduced authenticated management collections for the current Listing publisher and Property owner. Those endpoints intentionally deferred pagination and ordering while ownership behavior was being established. They currently load the complete owned collection, which creates an unbounded read as account data grows.

ADR-0039 already established a small transport pattern for bounded public collection reads: positive `page`, bounded `pageSize`, deterministic technical identifier ordering, and `hasMore` without a total count. No search, ranking, or business sort semantics are required to apply the same bounded-read principle to authenticated management collections.

ADR-0041 added single-column ownership indexes for the then-confirmed equality-only management filters. Once deterministic identifier ordering becomes part of the management collection query, the confirmed persistence access pattern becomes ownership equality followed by identifier ordering.

## Decision

`GET /api/market/listings` and `GET /api/market/properties` accept optional `page` and `pageSize` query parameters.

- `page` defaults to `1` and must be positive.
- `pageSize` defaults to `20`, must be positive, and must not exceed `100`.
- Invalid pagination returns `400` with the existing module-specific problem-details contract.
- Both responses are objects containing `items`, `page`, `pageSize`, and `hasMore`.
- Items are ordered only by the persisted resource identifier as a deterministic technical ordering.
- The Application asks persistence for `pageSize + 1` rows and derives `hasMore`; no total count is introduced.
- The actor identifier still comes only from the ADR-0025 mapped-user boundary. The client cannot choose an owner or publisher.
- Application code fails closed if an adapter returns a Listing for another publisher or a Property whose `OwnerUserId` does not match the mapped actor.

The repository interfaces retain their established ownership-list methods and add bounded page methods. PostgreSQL overrides the bounded methods with `AsNoTracking`, ownership filtering, identifier ordering, `Skip`, and `Take`. Default interface implementations preserve compatibility for simple test or non-PostgreSQL adapters by ordering and slicing the established owned result.

The ADR-0041 indexes keep their database names but are replaced by composite B-tree definitions matching the new access patterns:

- `ix_market_listings_publisher_user_id` on `(publisher_user_id, id)`
- `ix_market_properties_owner_user_id` on `(owner_user_id, id)`

The migration is reversible and restores the ADR-0041 single-column definitions on downgrade.

## Consequences

Management collection reads are bounded and deterministic without defining search, ranking, domain sorting, filtering, or total-count semantics. Existing direct resource operations are unchanged. This ADR does not define public Property presentation, Property removal, ownership transfer/delegation, additional Listing lifecycle behavior, or administrator workflows.
