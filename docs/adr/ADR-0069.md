# ADR-0069: Searching by map area

## Status

Accepted. Extends ADR-0065.

## Context

Visitors think in neighbourhoods more than in administrative districts. They want to move the
map to an area and see what is offered there. A naive bounding-box filter on exact coordinates,
however, would let anyone find a building by shrinking the box around a listing until it
disappears, which defeats the approximate locations of ADR-0065.

## Decision

- **API:** public search accepts `bbox=south,west,north,east` in decimal degrees.
  - Each side may span at most 8 degrees.
  - Invalid boxes return `400`.
  - A box on its own is a complete search, and saved searches keep it.
- **Matching uses the snapped grid point** (0.004°, the same one the public API exposes), never the
  exact coordinates. A box that does not contain the grid point finds nothing, however close it is
  to the building; this is verified against PostgreSQL.
- **Portal:**
  - The search map shows "ابحث في هذه المنطقة" once the visitor pans or zooms. Programmatic
    fitting does not count as a move.
  - The search keeps the other filters and goes back to page 1.
  - Area searches open with the map expanded, are titled "ضمن منطقة على الخريطة", offer
    "إلغاء حدود الخريطة", and are `noindex`.

## Consequences

- Precision is limited to about 400 m, which suits neighbourhood browsing.
- Listings without a pin never match an area search.
