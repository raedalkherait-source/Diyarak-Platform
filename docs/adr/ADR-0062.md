# ADR-0062: Long-lived sessions with rotating refresh tokens

## Status

Accepted. Extends ADR-0052 and ADR-0056.

## Context

Phone sign-in issued only an access token that is valid for 60 minutes, so publishers had to sign
in again with a new SMS code every hour. That is costly in SMS fees and frustrating. Making access
tokens long-lived would make a leaked token dangerous for a long time.

## Decision

- **Sessions** (`Diyarak.Platform.Identity.UserSession`): each sign-in creates a session that
  stores only SHA-256 hashes of refresh tokens.
  - A session expires after 30 days without use and at most 90 days after sign-in.
  - Every refresh rotates the token.
  - Presenting the previous token within 30 seconds of a rotation is treated as **stale**: a
    parallel request lost the race, and nothing is revoked.
  - Presenting it later is treated as **reuse**: the whole session is revoked, because the token
    was probably stolen.
- **Token format:** `{sessionId}.{256-bit secret, base64url}`. The secret is compared in constant
  time.
- **Concurrency:** `identity.user_sessions.current_token_hash` is a concurrency token (migration
  `IdentityUserSessions`). When two requests rotate the same token, only one can commit, and the
  other gets `stale`.
- **API:**
  - `POST /api/auth/phone/verify` also returns `refreshToken` and `refreshTokenExpiresAt`.
  - `POST /api/auth/session/refresh` `{ refreshToken }` returns new access and refresh tokens,
    `401 identity.session.invalid`, or `409 identity.session.stale`.
  - `POST /api/auth/session/logout` `{ refreshToken }` always returns `204` and reveals nothing.
  - `POST /api/auth/session/logout-all` (authenticated) revokes every session of the user.
- **Portal:**
  - The access and refresh tokens are kept in separate `httpOnly` cookies.
  - Middleware renews the access token 2 minutes before it expires. It applies the new cookies to
    the current request, so server components see them, and to the response.
  - Prefetch requests never rotate tokens.
  - If a protected navigation loses a rotation race (`409`), it retries once instead of signing
    the user out.
  - An invalid refresh token clears both cookies.
  - "My listings" offers "sign out" and "sign out of all devices".
- With renewal in place, the recommended access-token lifetime is **15 minutes**
  (`Authentication:Phone:AccessTokenLifetimeMinutes`). The default of 60 stays for compatibility.

## Consequences

Publishers stay signed in on their devices for up to 30 days of inactivity without repeated SMS
codes. A stolen refresh token stops working as soon as it is used alongside the legitimate one.

Signing out revokes the refresh token immediately. Access tokens that were already issued stay
valid until they expire, which is at most one access-token lifetime.

Open work: removing expired sessions from the database, and listing active devices to the user.
