# ADR-0049: Management collection pagination Link headers

## Status

Accepted

## Context

ADR-0042 bounded the authenticated Market Listing and Property management collections with `page`, `pageSize`, deterministic identifier ordering, and `hasMore`. ADR-0043 subsequently established `Cache-Control: no-store` for all authenticated Market management responses. ADR-0048 added standard HTTP `Link` navigation to the anonymous public Listing collection, but the two management collections still require clients to construct adjacent page URLs themselves.

The already-defined management pagination state is sufficient to expose adjacent navigation without defining any new product ordering, filtering, search, total-count, or lifecycle behavior.

## Decision

Successful responses from these authenticated management collection routes expose HTTP `Link` navigation metadata:

- `GET /api/market/listings`
- `GET /api/market/properties`

The rules are:

- emit `rel="prev"` when `page > 1`;
- emit `rel="next"` when `hasMore` is `true` and `page + 1` is representable;
- preserve the effective `pageSize` in every emitted link;
- emit both relations, in `prev` then `next` order, when both apply;
- omit the `Link` header when neither adjacent page is available.

The links are relative API paths and use only the already-defined `page`, `pageSize`, and `hasMore` state. They do not introduce `first`, `last`, `totalCount`, cursor semantics, snapshot guarantees, search, filters, ranking, or business sorting.

Expected authentication, authorization, and validation failures do not expose pagination links because no successful page was produced. The ADR-0043 management cache policy remains unchanged: management responses continue to use `Cache-Control: no-store`.

The Host shares one pagination-link formatter across the public Listing collection and both management collections. This refactor does not change the ADR-0048 public Link contract.

## Consequences

Management clients can follow adjacent pages directly from response metadata without duplicating URL construction rules. Public and management collection links now use one Host implementation, reducing drift while preserving all existing authorization, representation, persistence, and domain behavior.

No database migration, Domain change, Application change, repository change, or additional query is introduced.
