# ADR-0063: Deleting draft listings

## Status

Accepted. Complements ADR-0057 (listing lifecycle).

## Context

Publishers create drafts while experimenting and had no way to remove them. Published listings
already have a lifecycle (pause, resume, close), and a closed listing stays in the database as a
record. Drafts were never public: nobody has viewed, contacted or reported them.

## Decision

- **Only drafts can be deleted, and deletion is permanent.** Published, paused, closed and
  suspended listings return `409 market.listing_delete.not_draft`; publishers close them instead.
- **API:** `DELETE /api/market/listings/{id}?version={n}` returns `204`. A non-owner gets the same
  `404` as for a missing listing (ADR-0023). A stale version returns
  `409 market.listing_delete.concurrent_modification`.
- **What is removed**, in one transaction through `IDraftListingDeletionStore`:
  - the listing row, deleted only if it is still a draft with the expected version;
  - its photo rows;
  - its property, but only if it belongs to the actor and no other listing refers to it.
- **Photo files** are deleted after the transaction commits. If that fails, unreachable files
  remain, but no row ever points at a missing file.
- **Portal:** a "حذف المسودة" disclosure on the draft editor, with a warning that deletion cannot
  be undone. The form carries the version it was rendered from.

## Consequences

- There is no undo. That is acceptable because drafts were never public.
- A separate port keeps the existing repository interfaces, and their many test fakes, unchanged.
