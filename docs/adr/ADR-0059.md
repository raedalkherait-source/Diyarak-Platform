# ADR-0059: Configurable HTTP SMS gateway for one-time codes

## Status

Accepted

## Context

Phone sign-in (ADR-0052) needs a real SMS provider in production. Providers that serve Syrian
numbers differ in their HTTP APIs: query-string GET, form POST or JSON POST, API keys in a
header or a parameter, and local (`09…`) or international number formats. International
providers that are common elsewhere may be unavailable because of sanctions. Hard-coding one
provider would make switching expensive.

## Decision

- New Integration `Diyarak.Platform.Messaging.Http` implements `IOtpSender` with
  `HttpSmsGatewayOtpSender`, described entirely by configuration
  (`Messaging:Sms:Http`):
  - `Endpoint` (HTTPS; plain HTTP only in Development), `Method` (`GET`/`POST`),
    `Encoding` (`Query`, `Form`, `Json`; GET requires `Query`).
  - `Parameters` and `Headers`: name → template. Templates may use `{phone}` (E.164),
    `{phoneDigits}` (`963…`), `{phoneLocal}` (`09…` for Syrian numbers), `{message}`, `{code}`
    and `{apiKey}`. Substitution happens in a single pass, so substituted values are never
    re-expanded. Query and form values are URL-encoded. JSON is produced by the serializer, not
    by concatenating strings. Header values containing line breaks are rejected.
  - `ApiKey` (from a secret store), `MessageTemplate` (default Arabic text, must contain
    `{code}`), optional `SuccessBodyContains` for gateways that return errors with HTTP 200, and
    `TimeoutSeconds` (1–60, default 10).
  - All settings are validated at startup.
- Select it with `Authentication:Phone:OtpSender = HttpGateway`, which is allowed in every
  environment. `DevelopmentLog` remains Development-only.
- Delivery failures (non-2xx, missing success text, timeout, unreachable) raise
  `OtpDeliveryException`, whose message never contains the code, the number or the credential.
  `RequestPhoneVerificationUseCase` maps it to `503 identity.phone.delivery_failed`. The stored
  challenge still counts towards the per-phone throttle, so retries against a failing provider
  are limited too.
- `System.Net.Http.HttpClient` logging defaults to `Warning`, so gateway URLs, which may carry the
  code or key in the query string, are not logged.

## Consequences

Any provider with a simple HTTP API can be connected through configuration alone, and switching
providers needs no code change. A provider that needs request signing, OAuth token exchange,
delivery receipts or WhatsApp templates needs its own adapter behind the same `IOtpSender` port.
Sending through two providers with automatic fallback is open work.
