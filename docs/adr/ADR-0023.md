# ADR-0023: Assign Market Listing publication ownership to its creator

**Status:** Accepted

## Decision

Every Market Listing will have a required immutable `PublisherUserId` represented by a non-empty `Guid`.

`PublisherUserId` identifies the authenticated platform user who created and owns the Listing publication workflow. It remains an opaque identifier in `Diyarak.Market.Listing`; the module does not depend on the Identity implementation.

Publication authorization is creator-only: an authenticated user may publish a Listing only when their user identifier equals the Listing's `PublisherUserId`.

This authorization check belongs to Application orchestration. It must occur after loading the Listing and before checking Property existence, changing domain state, or saving the Listing.

`PublisherUserId` is distinct from `ListingContext.PublishingRole`. The publishing role describes the publisher's declared relationship to the Property and does not prove identity, ownership, or permission.

The Host remains responsible for authenticating the caller and supplying the authenticated user identifier to the Application use case.

An authenticated caller whose user identifier does not match `PublisherUserId` is treated as unable to observe the Listing. Application orchestration returns the same `market.listing.not_found` outcome used for a missing Listing. The HTTP contract therefore maps both cases to `404 Not Found`, preventing disclosure of resource existence.

ADR-0024 defines the persistence migration strategy for the required Listing owner.

The authentication mechanism, claims mapping, Listing creation workflow, administrative override permissions, ownership transfer, and endpoint exposure remain separate decisions.
