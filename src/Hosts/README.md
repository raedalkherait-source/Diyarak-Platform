# Diyarak Hosts

Hosts compose the Diyarak application and contain no business rules.

Current host:

- `Diyarak.Api` — ASP.NET Core composition host for platform integrations and business modules.

ADR-0030 defines authenticated `POST /api/market/properties` creation for the already modeled Property fields, returning `201 Created` with the server-generated Property identifier. ADR-0031 adds authenticated `GET /api/market/properties/{propertyId}` direct loading. ADR-0034 assigns the mapped internal actor as owner for every new Property and makes that direct read owner-only with concealed `404` for missing, non-owned, and legacy-unowned resources. ADR-0035 adds mapped-user-only `GET /api/market/properties` for the current owner's management collection, excluding other users' and legacy-unowned rows. ADR-0036 adds owner-only full replacement through `PUT /api/market/properties/{propertyId}` with a required positive expected `version`; successful replacement returns `200 OK` with the new version, stale versions return `409 Conflict`, and missing, non-owned, or legacy-unowned Properties retain concealed `404` behavior. ADR-0042 bounds that management collection with `page`/`pageSize`, deterministic identifier ordering, and `hasMore`; ADR-0049 adds `prev`/`next` Link metadata to successful pages without changing the body, `no-store` cache policy, public Property discovery, search, or business sorting.

ADR-0022 defines the Market Listing publication contract as `POST /api/market/listings/{listingId}/publish`, with `204`, `400`, `404`, and `409` outcomes represented through HTTP status codes and RFC Problem Details where applicable. ADR-0026 defines `POST /api/market/listings` for creating an actor-owned `Draft` Listing for an existing Property, returning `201 Created` on success.

ADR-0023 permits publication only for the authenticated creator identified by the Listing's immutable `PublisherUserId`. A non-owner receives the same `404 Not Found` response as a missing Listing.

Market Property management routes and authenticated Market Listing management routes are mapped only when `Authentication:Enabled` is `true`. They require the ADR-0025 `mapped-user` authorization policy, which resolves the exact external `(iss, sub)` identity to an internal `User.Id`. ADR-0043 marks those management endpoints with `Cache-Control: no-store` at the Host boundary, including responses produced by authentication/authorization short-circuiting; anonymous public Listing routes are not assigned that management cache policy. Listing and Property orchestration receive only that mapped internal identifier as their actor; Property creation persists it as internal management `OwnerUserId`, never from request data. The Listing creation route never derives `PublisherUserId` from request data and, under ADR-0037, permits creation only when the mapped actor owns the referenced Property. Missing or invalid access tokens return `401`, valid but unmapped external identities return `403`, and mapped non-owners retain concealed `404` behavior for owner-controlled Listing operations and ADR-0034 Property direct loading. ADR-0035 Property collection reads are filtered to the mapped internal owner; after ADR-0042 an owner with no rows receives an empty `items` collection inside the bounded page response.

ADR-0029 adds authenticated owner-only `PATCH /api/market/listings/{listingId}` Draft editing with explicit Listing-version conflict handling. ADR-0032 adds creator-only `GET /api/market/listings/{listingId}` direct loading with the same concealed `404` behavior for non-owners. ADR-0033 adds mapped-user-only `GET /api/market/listings` for the authenticated creator's own management collection; ADR-0049 adds adjacent-page `Link` metadata to successful bounded management pages using the same page coordinates and `hasMore` state defined by ADR-0042. ADR-0038 adds anonymous `GET /api/market/public/listings/{listingId}` for published Listings only. ADR-0039 adds anonymous `GET /api/market/public/listings` with `page` defaulting to `1`, `pageSize` defaulting to `20` and capped at `100`, deterministic `ListingId` ordering, and `hasMore`. Both public responses omit management version/status, publisher ownership, and subject identifiers, and both routes remain mapped even when OIDC management authentication is disabled. ADR-0044 adds a strong opaque `ETag` plus `If-None-Match`/`304 Not Modified` revalidation to direct public Listing detail. ADR-0045 extends that conditional revalidation to each public Listing collection page with a page-specific opaque validator derived from page coordinates, `hasMore`, and the ordered Listing identifier/version sequence. ADR-0046 applies `Cache-Control: public, no-cache` to successful public Listing responses and their `304` revalidation responses, and `Cache-Control: no-store` to expected public `400/404` responses; no positive public freshness lifetime is defined. ADR-0047 maps `HEAD` alongside `GET` for both public Listing resources and reuses the same validation, visibility, pagination, ETag, `If-None-Match`, and cache-policy logic while returning no body. ADR-0048 adds `Link` response metadata to successful public collection pages: `prev` is present for pages after the first, `next` is present only when `hasMore` is true and the next page coordinate is requestable, and GET, HEAD, and `304` responses expose the same page navigation without defining `totalCount` or `last`. ADR-0049 centralizes that Link formatter and applies the same adjacent-page convention to authenticated Listing and Property management collection GET responses; management responses remain `Cache-Control: no-store`. Search/filter/ranking semantics and public Property presentation remain undefined.

Other Diyarak Market public and administrative endpoints remain pending concrete endpoint and authorization requirements.
